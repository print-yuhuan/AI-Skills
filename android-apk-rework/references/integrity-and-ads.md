# 内置完整性校验与广告关闭实操

用于重签后完整性报错、连接失败，以及去广告后留下遮罩或等待。下面的名称、字段和状态仅为检索线索；地址、参数位置、摘要编码和返回 ABI 均须由当前 APK 确认。

## 从报错追到真实检查

先定位错误字符串的引用和异常转换，记录触发阶段及调用链。可对反编译目录、AOT 汇编和已提取的原生字符串索引分组检索：

```text
客户端完整性验证失败 / 暂时无法连接
SigningInfo / MessageDigest / EXPECTED_CERT / VerifyRelease
MethodChannel / native_operation / integrity / release
```

| 层次 | 核对对象 | 修改与验收依据 |
| --- | --- | --- |
| Android 安装签名 | APK 签名块与证书 | apksigner 验证；不代表应用接受该证书 |
| Java/Kotlin 自校验 | provider、Application、启动方法中的证书比对 | 查失败分支及副作用；同步已确认的预期摘要 |
| 原生内容校验 | JNI/Go 初始化、显式验证入口中的 DEX/SO/整包摘要 | 查真实校验函数及各调用方；与证书常量分开处理 |
| 服务端校验／授权 | 同步响应、完整性证明、激活状态、运行配置 | 以实际响应与目标功能为证据；本地返回成功不代替服务器接受 |

“客户端完整性验证失败”可能来自 provider，也可能是 native 错误经桥接转换后的提示。“暂时无法连接”可能统一包装网络、初始化、缺配置或授权失败。提示消失只能证明该路径未再报错，不能证明连接已经修复。

先检查本地验证是在发送请求前失败，还是请求后的响应被拒绝。进程存活、首页打开、取得配置、建立连接及实际流量分别记录；原包对照保持同设备和可比会话，不为对照自动卸载或清除用户数据。

## 证书同步与原生检查分开修改

1. 读取 Manifest 注册的 provider/Application，沿 `onCreate`、`attachBaseContext`、初始化和显式验证入口追踪。Flutter 包同样检查 DEX 与 JNI 层，不能只处理 libapp.so。
2. 查证书来源及比较过程：旧 `signatures`、当前签名者、签名历史是否有不同分支，摘要输入是否为证书 DER，输出是否为十六进制或 Base64。相关 API 语义见 [Android SigningInfo](https://developer.android.com/reference/android/content/pm/SigningInfo)。
3. 已确认是预期证书不匹配时，使用最终签名证书的摘要更新指定常量，保留签名数量、调试标志及无关检查。固定沿用该修改版密钥；多轮修正不要重新生成证书。
4. 常量走 Smali 重组装，只替换声明 DEX；不能直接改 DEX 字符串后仅修 checksum。最终包重反编译并核对修改方法，具体结构故障见 [startup-popups-crashes.md](startup-popups-crashes.md)。

若实际比较的是证书 SHA-256 的 Base64，转换的是原始摘要字节：

```python
import base64
expected_b64 = base64.b64encode(bytes.fromhex(certificate_sha256_hex)).decode('ascii')
```

不要计算 APK／密钥文件摘要，也不要 Base64 编码十六进制文本。若校验结果用于解密或派生密钥，同步比较值仍可能不足，须继续追踪下游。

原生内容检查另建补丁记录。先找 JNI 导出、初始化与错误转换，再定位实际校验函数，核对是否被初始化和显式验证重复调用；补丁落在已确认的检查边界，保留运行配置加载、资源释放及其他初始化。

混淆 Go 符号或函数表只能提供候选入口。恢复范围时结合 ELF 重定位、导出桥接地址和实际调用目标核对地址基准；函数表中的零值或相对地址不能直接当 VA，不能根据最近的混淆函数名选补丁位置。

尤其不要把 Go `error` 当一个布尔值：接口值包含类型与数据两部分，按当前 ABI 确认 nil error 的返回方式，只清数据指针可能仍留下非 nil 接口。Go 内部 ABI 与 C 导出包装不同，不能把 JNI wrapper 的参数／返回寄存器套到内部函数；说明见 [Go 内部 ABI](https://github.com/golang/go/blob/master/src/cmd/compile/abi-internal.md)。

修改前检查序言、栈增长检查、异常／错误路径、锁与 defer。无帧叶返回必须发生在尚未建立原栈帧的位置；已建帧或持锁路径只能复用正确恢复、解锁的尾部。guard、重新反汇编和栈／分支模拟分别保留证据，模拟范围不能扩展为真机或服务端验证。

## 按广告生命周期选择入口

优先修改专用加载／展示入口或仅用于广告的共享可用性判断。先读其调用方，再决定返回值和回调；一个共享 gate 可能同时控制横幅、激励或启动就绪，不能假定关闭后没有业务影响。

| 广告类型 | 适合的处理点 | 关闭后仍需完成 |
| --- | --- | --- |
| 开屏 | 专用加载／展示入口 | 原清理、视图销毁、遮罩释放、完成回调及 ready 通知 |
| 横幅 | 专用可用性判断、加载与刷新调度 | 取消刷新／重试、释放容器，保留非广告业务 |
| 激励 | 专用展示入口 | 按原协议发送无广告／取消终态，关联本次请求，结束 Future 与按钮等待 |
| 推荐／图片推广 | 独立请求、缓存、调度入口 | 清旧缓存并结束 loading；参考启动文档中的独立服务路径 |

广告 SDK 初始化可以关闭，但先核对应用是否依赖它的初始化完成回调、前台标志和 ready 握手。原 SDK 调用被跳过后，用应用已有无广告完成路径更新这些状态；不要将尚未就绪的账号、线路或资源初始化标成完成，也不要全局禁用其他 SDK。

复用清理方法前核对 nullable 参数、重复调用、已销毁视图及完成通知次数。SDK 文件可以保留，只要确认应用加载／展示入口和后续重试已关闭；删除包内所有广告类或库会引入未处理引用，不应作为默认方案。

## 激励回调必须关联正确请求

跨 Flutter MethodChannel 的流程常包含：创建请求 → 保存请求编号 → 展示 → 收到状态 → 匹配编号 → 完成 Future／恢复按钮。先检查调用参数、native 字段赋值、回调 map 和 Dart 消费方，按语义确定编号，不能靠字符串参数次序猜测。

例如，当前样本若已证实调用是 `show(userId, extraData, attemptId)`，返回应关联第三个参数：

```kotlin
// 示意：字段名和终态必须与当前 Dart 消费方一致。
fun show(userId: String, extraData: String, attemptId: String) {
    channel.invokeMethod("state", mapOf(
        "state" to "unavailable",
        "attempt_id" to attemptId
    ))
}
```

若它是 Smali 实例方法且三个参数均为单槽 String，`p0` 是 this、`p1/p2/p3` 才分别对应三参；静态方法、宽参数及其他签名重新计数。`extraData` 与 `attemptId` 类型相同，传错能通过组装和 ART，却会被 Dart 当作过期请求忽略，界面长期显示“正在准备”。

同时核对回调是否已注册、同步发出会否早于消费方登记，以及清理是否会影响下一次请求。按钮卡住时记录卡在广告就绪、请求创建、展示回调还是服务端轮询；不要用统一清 loading 掩盖未结束的 Future、定时器和旧请求。

以两次连续点击、失败后重试、退到后台再恢复、同签名覆盖后恢复旧待处理请求验证终态和编号。验证按钮恢复可用及无重复通知；只看到广告未出现不足以验收。

## 广告关闭与额度授权分别判断

有些应用由服务器返回未激活／已激活状态，未激活响应不含运行配置；观看激励后才取得新的配置或有效期。静态分析应追踪请求创建、激励确认、状态轮询和配置同步，真机验证则确认实际状态及连接结果。

关闭本地到期／剩余流量判断，只能影响已有模型或配置的客户端使用路径；不能产生缺失配置，也不能延长服务器凭据或流量授权。保留关闭状态、缺配置拒绝及锁释放等必要处理，不把所有可用性判断都强制为 true。

禁用广告还可能关闭正常续领额度的途径。交付分别标记广告展示关闭、等待修复、本地限制修改、完整性提示复测、服务端授权和实际连接。无广告但仍锁定的包必须明确写目标未完成，不能称为无限版，也不能以伪造本地激励成功作为服务端发放证据。

## 最小真机验收

| 场景 | 观察与记录 |
| --- | --- |
| 冷启动与同签名覆盖后启动 | 实际 APK 摘要、PID／前台、完整性提示、遮罩和广告 |
| 激励无广告／取消路径及重复请求 | 返回编号、终态、按钮可用性、残留等待和重试 |
| 初始化未就绪／错误／后台恢复 | 不跳过必要初始化、不重复导航或完成通知 |
| 配置存在／缺失、额度有效／耗尽 | 客户端判断与服务端响应、实际功能分别验证 |

日志与 UI 绑定当前修订及实际进程；服务端会话和令牌不进入技能库。安装警告、已安装版本核验及 DEX 等价比对见 [packaging-validation.md](packaging-validation.md)，PID／前台归属见 [isolated-diagnostics.md](isolated-diagnostics.md)。
