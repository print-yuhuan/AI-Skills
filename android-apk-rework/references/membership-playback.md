# 会员权益、权限谓词与完整播放

用于返修“基础会员已开通但部分功能仍锁定”“显示最高会员却只播几秒”“详情没有线路”等问题。

## 最高卡先确认配置，再确认权益

把用户指出的当前卡与目标卡映射到当前版本实际返回的产品配置，记录卡名、等级字段和取得方式。可读静态枚举、比较阈值或隔离运行时的卡配置；不要按名称、价格、列表顺序或其他 APK 猜编号。

多个产品可能共享同一个 `vipLevel`。基础永久卡和目标最高卡都为 2 时，调大数字或只改卡名没有证据能补齐权限。继续检查用户状态中的独立会员 bool、模块许可、到期时间、免费/金币视频有效期及额度，并追踪哪些字段被实际功能读取。个人页的到期时间只证明显示值，不能直接断言它就是播放失败原因。

目标卡没有出现在当前会话配置中时，记录缺失；不能从另一张卡的等级推导目标卡，也不能把所有应用都套用同一个最高值。

返修既有补丁时，检查固定赋值是否把真实高等级压低。若业务证据支持采用客户端等级下限，保留原 JSON 读取、类型检查和较高值，只在已确定的用户状态路径设置下限。内容模型中的 `vipLevel` 可能表示观看门槛，不是用户等级；不要给所有同名字段套下限。如果既有值已等于目标卡等级，不能把重复写入相同数值计作权益修复。

区分以下状态：

| 状态 | 所需证据 |
| --- | --- |
| 目标卡数字确认 | 当前版本配置或明确枚举/比较依据 |
| 客户端权限已改变 | 实际谓词、字段类型及调用方行为 |
| 目标权益已生效 | 对应功能的实际运行结果；服务端权益另看响应 |
| 完整视频已验证 | 实际资源时长、持续播放及拖动等具体场景 |

## 从播放链路判断剩余限制

```text
用户状态 → 列表/详情权限 → 播放请求参数
        → 响应模型 → 完整/预览地址选择 → 播放器计时与暂停
```

详情 API 和播放 API 可能返回不同模型，甚至只有详情路径改过预览标志。逐一查真实调用，避免把相邻的详情包装器当成播放请求。参数也可能只有视频 id，本地会员数值根本没有提交；先读参数构造，不凭 UI 推测服务器知道本地等级。

检查响应中的完整地址、预览地址、预览标志、权限错误、线路列表及缺字段分支。完整地址为空时回退预览，或者旧包已把 `is_preview` 写为 false，都不能让短资源变长。进度条显示完整片长可能只是详情元数据，不是媒体时长证据。

为核查资源选择收集必要的状态、字段是否存在、地址长度或摘要、响应类型等元数据；分享报告不包含令牌、账号、完整资源 URL 或媒体内容。不要猜测 URL 前缀替换、拼接完整路径或把预览响应伪装成完整线路。

服务端拒绝授权、只返回预览和客户端提前暂停是不同故障。只有取得对应响应才作归因；一个样本的结果不能推广到其他应用或全部视频。缺少完整资源证据时，继续可独立完成的客户端修复，同时明确剩余项；不要靠继续抬高等级重复生成同效果 APK。

## Kotlin 协程桥接与空线路

遇到 Java/Kotlin 应用需要把原播放结果接入详情线路时，先核对实际 APK 的类、方法、字段和 JVM 描述符。编译桩不能凭源码名称猜类型；例如暂停标记可能是 enum 类型，按 `Object` 描述符编译即使成功，也会在 ART 出现 `NoSuchFieldError`。

保留原 `Continuation` 的 context、恢复、异常和取消语义，区分同步返回与 `COROUTINE_SUSPENDED`，不能恢复两次或递归重试。已有线路时不重复请求；需要补线路时沿用原播放 API 参数，只在实际响应允许且地址有效时补入符合原类型的线路。保留原最终字段，必要时使用独立适配字段，避免破坏序列化和其他读取方。

用有意义的同步/挂起、成功/失败/取消、有线路/空线路、预览/完整夹具验证桥接，并在隔离 ART 加载实际交付 APK 的类测试描述符。夹具通过和进入详情不崩溃都不证明真实完整资源可用。
