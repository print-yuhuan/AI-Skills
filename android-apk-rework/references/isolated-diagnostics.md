# 隔离运行诊断与二进制 Manifest

在没有方便的手机调试条件、需要临时调试标志或读取运行元数据时使用。诊断应服务于明确待确认的问题，避免为了收集更多证据反复搭建环境或重测未受影响的包。

## 会话、设备与证据归属

复用适配当前 ABI 的隔离模拟器；每次显式指定 serial，安装或卸载前确认目标模拟器身份。原包对照、清数据、卸载等操作只作用于该隔离环境，不把它们扩展到用户手机。

操作 UI 前确认目标包 PID 存在且前台 activity 属于目标包；读取日志按目标 PID 过滤。应用提前退出后，截图/UI dump 可能来自上一款应用，不能拿它的首页作当前包启动成功证据。空 UI 节点可能是尚未加载，应有限等待并复查进程、前台和错误；不能仅按固定等待秒数判断完成。

访客/自动生成账号是有效测试路径，不强制转成普通账号登录。新模拟器访客与用户原有访客会话不同。记录认证异常与其接口/阶段；原包与修改版都出现同类错误时，不归因于补丁，也不根据请求数不同比较质量。

## 诊断包与正式包分离

诊断 Manifest、采样代码和临时 provider 调试分支分别记录，只在独立诊断包中使用。需要 `run-as` 时，`debuggable=true` 可能被应用自身的反调试检查拦截；先定位，按诊断需要调整该标志检查，保留其他检查。正式重签名仍按实际证书同步预期摘要。

正式包从明确的原始或前一正式修订构建，保留其 Manifest 和未声明成员。恢复安装正式包后再做验证，最终索引不能引用诊断包路径或日志中的旧修订。

## AXML 修改的非直观问题

混淆 APK 的原始二进制 Manifest 可能含不能正常表达为文本 XML 的属性，或工具不支持的字符串池布局。仅为调试而重建资源可能改变资源标识、引入无效 XML或丢失原属性。正式包不需要 Manifest 修改时，直接保留其原始字节。

确需二进制插入调试属性时，使用能验证该布局的解析器，保留旧字符串索引、namespace 和 resource map，并同步 chunk 长度、属性计数以及 id/class/style 索引。新增属性按 framework resource id 的有效顺序插入；仅在 `<application>` 末尾追加，可能安装成功却不被 typed-attribute 读取接受。按所用格式处理对齐，不能假定混淆 attribute stride 就是标准 20 字节。

字符串池的声明数量与 offset 区间不一致时，不猜数量并强行归一化；只有证明全部已引用字符串索引、样式及数据区都仍有效，才可在独立诊断包处理。遇到未支持布局停止该变换，保留输入并换受支持的工具/方法。

检查编译/安装结果及实际 application flags，再验证 `run-as`，不能以 XML 中有 `debuggable` 或安装成功代替。Windows 原生 aapt2 若不能打开中文工作路径，可为其解码/重建目录选择 ASCII 路径；签名产物名称仍可保留中文。

## 最小运行元数据采样

静态信息不能确认卡等级时，可在已定位的产品解析器采集卡名和解析后的整数。采集点先确认类型与 ABI，只输出获准的最少字段，不转储 JSON 对象、堆内存、账号、令牌、URL 或媒体。

若采用 AOT 叶片段，确认它不触发 VM 分配/调用/安全点；保存所有会被修改的寄存器及需要恢复的 NZCV，检查软件栈空间、字符串 CID/长度和 syscall 失败路径。Linux syscall 号、允许的寄存器破坏及 String 布局均按当前平台核对。先模拟有效字符串、错误类型、栈限制、打开失败及继续执行路径，再测隔离运行；模拟不证明 VM 安全。

只把新增代码放入已核查、未被段/节占用的文件填充区，按 [flutter-aot.md](flutter-aot.md) 核对 ELF 映射；空间不足时减少采样或换方法，不覆盖相邻段。不要直接复用历史地址、线程偏移、CID 和私有包路径。

对已经生成 `<qII>`（已解码的有符号等级、字符串 CID、字节长度）头及原始名称字节的采样文件，可用 [../scripts/decode_card_trace.py](../scripts/decode_card_trace.py) 校验/解码。它只解析这个明确定义的格式，不注入 APK，也不确认会员权益；CID 需从当前样本取得。

```text
python scripts/decode_card_trace.py --input <采样文件> --out <新JSON文件> --one-byte-cid <当前CID> --two-byte-cid <当前CID> --highest-name <目标卡准确名称>
```

脚本保留负数、不同卡名共享等级以及同名不同等级记录，目标卡只按名称精确匹配。输入大小与名称长度有界，未知 CID、截断记录及无效 UTF-16 会报错，输出已存在时拒绝覆盖。其合成用例可在技能目录运行 `python -m unittest discover -s scripts -p test_decode_card_trace.py`；不用真实访客或卡数据作测试夹具。
