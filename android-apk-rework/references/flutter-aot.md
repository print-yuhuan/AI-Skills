# Flutter / Dart AOT 定位与补丁

在发现 `libapp.so` 与 `libflutter.so` 且需求位于 Flutter 业务层时阅读。下面 ABI 特征必须在当前二进制确认。

## 分析基线

1. 按 ABI 成对提取同一 APK 的 libapp/libflutter，不混用不同包或版本。
2. 记录 ELF 架构、Dart 版本/通道和快照特征，使用匹配的解析器。工具未支持时先查失败，再决定适配或换工具。
3. 本次 Windows 用 WSL 构建对应 Blutter，按样本保存构建日志与输出；复用已构建工具。WSL 和某个 Linux 版本不是通用硬要求。
4. 保存 `asm/`、`pp.txt`、`objs.txt` 与函数/交叉引用索引，字符串命中只是线索。

Blutter 的输入是包含库的目录，输出有分析后的汇编与对象池信息；支持范围、安装和参数以当前版本为准：[Blutter 官方仓库](https://github.com/worawit/blutter)。

例如在已准备好工具的环境运行 `python blutter.py <同一ABI的库目录> <新的分析输出目录>`；Windows/WSL 路径转换仅在该环境需要。先查看版本识别与构建日志，再用 `rg` 在输出中检索目标字段和函数，不从其他样本借用分析结果。

## 定位路径

```text
API/缓存 → JSON 取值及类型检查 → 模型构造/赋值
        → 权限 getter/谓词 → 播放/弹窗控制器 → 实际副作用
```

搜索 `is_preview`、`has_play_permission`、`is_purchased`、`is_free`、`vipLevel`、价格、公告、路由和广告键。检查 snake_case/camelCase、拼写错误及缺字段分支，不假定第一处命中就是最终入口。

对象池引用可能直接 `ldr [PP, offset]`，也可能先 `add` 大偏移；`ldp`、寄存器重用与跨指令引用会被简易注释器漏掉。缺注释不代表缺引用。

不完整符号的最近函数名、只按 `stp FP, LR` 切分范围，都只是启发式。结合入口、终止路径、交叉引用、异常/异步恢复和尾调用确认边界；无标准序言的叶函数不能因此丢弃。

Windows 大小写不敏感目录可能让不同 Dart 库的同名/仅大小写不同汇编文件互相覆盖。保存原分析结果，按稳定序号或入口地址生成唯一文件名，并与索引关联；不能因为文件名匹配就相信内容归属。大型单行函数/引用 JSON 用结构化读取筛选，不用 `rg` 打印整行。

## 值与布局

本次部分 ARM64 构建中软件栈是 `x15`，FP `x29`，THR `x26`，PP `x27`，null 基址 `x22`；true/false 表现为 `null + 0x20/0x30`，Smi 是整数左移一位。这些不是跨版本补丁接口。

- native 整数直接存储；Smi 输入可能先解标签再写 native 字段。
- 压缩对象/布尔指针通过 `stur wN` 写入，读取可能补回 heap base。
- 常量必须满足字段类型，不能把任意 `0/1` 当 Dart bool。
- 优先替换类型验证后的最终赋值输入，保留分配与写屏障；检查另一份解析器或 cache/fromJson 路径。

本次 Dart 3.12.2 stable、3.12 beta、3.2.6 的 THR 静态表/栈限制偏移和参数 ABI 不同，不能复用字节模板。

压缩 Smi 的低位是有符号值；若高 32 位保留了无关值，不能对整个寄存器做无符号右移后当等级。按当前表示确认有符号解码（部分 ARM64 样本使用 `sbfx ..., #1, #31`），至少检查负数、零、基础值、更高值及 null。叶补丁若需保留 boxed int/Mint，保持其指针及原类型处理，不把奇数指针当整数比较。数据记录也用有符号类型，避免把 -1 报为巨大等级。

## 返回值读调用方

| 谓词语义 | 解除本地拦截的方向 |
| --- | --- |
| 非空视频允许播放 | 允许，保留空对象拒绝等必要处理 |
| 需要购买/会员拦截 | 不需要拦截 |
| 当前在允许的试看时间段 | false 可能触发暂停/购买，不能当“取消试看” |
| 应显示试看结束提示 | 结合实际分支关闭提示与中止行为 |

读返回值后的 `tbz/tbnz`、暂停、计时和购买调用。仅改会员文字、图标或等级，不足以确认视频解锁。

## 异步与栈帧

async 方法保留初始化和正确完成路径，不用普通 `ret null` 随意代替 Future 返回。关闭专用弹窗入口可在 `InitAsync` 后跳到该函数已有空完成分支，前提是帧与异常范围匹配。

跨函数跳转、不可达代码 helper、复用其他函数尾部需要考虑 VM 的 PC 描述、栈图、GC 活跃槽及异常范围。Unicorn 中软件栈恢复正确不保证 Dart VM 可接受。优先原函数内修改；原导航回调与帧通常更易验证。

需要替换缓存集合时，优先复用原函数的类型正确空列表分配和字段写入路径。清空动作应覆盖已有缓存，且更新对象指针时保留原写屏障及其 VM 已注册调用位置；在新增叶代码中发起分配或写屏障调用不能仅凭指令模拟保证 GC 正确。

新增无调用叶片段仍需核对 ELF：VA 经 `PT_LOAD` 映射，填充字节为零且不属于现存段/节，扩展 RX 的 file/memory size 后仍在下一段之前。按实际 4KB/16KB 装载布局检查页面重叠和对齐；`zipalign -P 16` 无法修复 ELF 段布局。没有足够安全空间时停止该布局方案，不覆盖数据或仅修改表面长度。

## 指令检查

依当前架构选用 Capstone、ELF 工具和 Unicorn：验证原指令 guard、分支目标、构造/存储序列、解标签后整数与 bool、缺字段/空对象、ready/pending 和 FP/LR/软件栈恢复。

把 VM 初始化、分配或路由等 mock 边界写入报告。不把模拟结果扩大为 GC、播放、登录或 Android 启动通过。
